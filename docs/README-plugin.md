## 功能

- 🎙️ **语音输入**：麦克风 → 桥接 FunASR 中文识别 → 注入对话（连续聆听、自动端点）
- 📷 **实时画面**：摄像头按钮打开后按摄像头自己的帧率（本机 30 fps）持续取帧
- 🎞️ **只留有变化的帧**：每帧带一个 32×24 灰度指纹（桥接算，768 字节），和**上一张留下的帧**比对；平均差越过 1.0 才留一张，静着不动就一张都不留。留到 80 张为止，再多就把最旧的挤出去
- 🗣️ **画面随麦克风一起攒**：麦克风亮起那一刻开始攒，攒下的帧在舰长开口时按时间顺序附在那句话前面一起送进模型，送完清空
- 🖼️ **摄像头小窗**：右下角小窗显示摄像头实时画面（跟着采样帧率走），底下一行写明模型最后一次收到画面的时间；可以拖动，位置会记住
- 🔛 **三个开关自由组合**：麦克风（听）、喇叭（说）、摄像头（看）各自独立，按亮即生效，没有模式菜单也没有预设
- 📹 **画面只来自本机摄像头**：由本地桥接直接开电脑摄像头取帧（OpenCV），**不经过浏览器、不弹任何权限申请**；关掉摄像头时设备立刻还给系统
- 🎞️ **本地视频交给模型看**：视频存本地后，把路径给桥接即可得到描述（DSH 会话层只有 text|image 模态，原始 mp4 附件模型看不到画面，这一步由桥接代打）
  ```bash
  curl -s -X POST http://127.0.0.1:8765/api/vision -H "Content-Type: application/json" \
    -d '{"path":"E:/videos/test.mp4","prompt":"这段视频里发生了什么？"}'
  ```
- 🔊 **语音回复**：回复流式 TTS 朗读（**本地 GPT-SoVITS 推理**，固定一份参考音色）
- ⚡ **插话/排队**：亮=说话打断回复；灭=回复读完句子排队接上
- 👧 **数字人窗口**：右侧动画窗（空闲/说话视频，素材自备），自动贴右侧插件边缘不被遮挡
- 🎭 **两类预设一键切换**：工具行两个按钮分别循环切换 **数字人形象 / 待机动画**，选择自动记忆（localStorage）。待机（`assets/bg-images/<名字>/`）、形象（共享卷 temp 放 mp4）均可自行添加，无需改代码

## 使用前提

1. 克隆主仓库并按其 README 装好 voice bridge（`start-all.cmd` 一键）
2. 本插件的桥接地址默认 `http://127.0.0.1:8765`（localStorage `s2s.voice.bridge` 可改）

### 视觉相关配置（bridge-config.json）

```jsonc
"vision": {
  "enabled": true,
  "api_key": "",                 // 留空则读环境变量 MINIMAX_API_KEY / MINIMAX0_API_KEY，或 ~/.dsh/.credentials.yaml
  "base_url": "https://api.minimaxi.com/v1",
  "model": "MiniMax-M3.1-Flash",
  "fps": 1.0,                   // 视频的抽帧率（0.2 ~ 5）
  "ffmpeg": "E:/tts/ffmpeg-.../bin/ffmpeg.exe"   // 非 MP4 容器时的转换
},
"camera": {
  "enabled": true,
  "device_index": 0,             // 电脑摄像头序号
  "max_side": 640,               // 取帧缩放后的最长边
  "quality": 60                  // JPEG 质量
}
```

> 摄像头由桥接自己开（`GET /api/camera/frame` 取一帧，`POST /api/camera/release` 归还设备）。桥接内部有一条常驻读帧线程按设备帧率连着 grab，HTTP 只负责「取最新一帧 + 编码 + 算指纹」，所以 30 fps 也很轻（实测单帧 2 毫秒左右）。无人取帧超过 60 秒会自动关设备，摄像头的灯不会一直亮着。

### 为什么没有「观察轮次」

DSH 的会话层只有一条把内容送给模型的通道：`session.prompt()`。凡是通过它送进去的内容，都会作为一条用户消息留在对话记录里，没有隐形/后台通道。所以「让模型按固定节奏自己开口」和「界面上不出现这些消息」无法同时成立。本插件选了后者：帧在后台攒，等舰长开口时随那一轮一起送——界面保持干净，代价是模型不会主动开口评论画面。

### 一轮带多少帧：拼图（v0.4.0 起）

旧做法是「攒到 80 张，一轮全发出去」。实测一轮就是 **3.3 万视觉 token**（80 张 640×480，provider 侧实测），几轮就把上下文撑满，紧接着撞上压缩失败——延迟和钱都花在这里。

现在改成**拼帧**（思路来自 [dsh-see-now](https://github.com/SAOS-3624/dsh-see-now)，Apache-2.0）：

- **打分**：桥接每帧顺带算一张 64×36 的 HSV 网格（`/api/camera/frame?grid=1`，OpenCV 一次 resize + 一次转 HSV），插件按「色相环形差 + 饱和度降权 + 明度差」算出 0–255 的变化分。打分 12 fps，与 30 fps 的预览取帧互不干扰
- **留帧判据**：三条——切点（分数 ≥ 12 且是邻帧的 2.5 倍以上、距上刀 ≥ 0.4 秒）、积分（每帧分累加，攒够 `5 × 12 × 3 = 180` 才留一帧，画面越动越密；安静的房间永远攒不够，一帧都不出）、兜底（静满 20 秒给一张）
- **拼图**：留下来的帧等分排进一张 1024 宽的画布（格子保持源画面宽高比，不裁不压扁，帧号烧在左上角），另附一张最新帧的全幅图
- **上限**：一张拼图最多 9 格（3×3 铺满）。格子数按平方数跳档（1 / 4 / 9 / 16），同一档里多塞几帧既不涨 token 也不缩格子，所以上限就是当前档位的满格数；超了挤掉「和左右邻居最像」的那张，首尾不动

结果：同样一轮，旧路径 80 张、约 3.3 万 token；拼图路径 1 张拼图（约 500 token）+ 1 张全幅（约 206 token）。

**阈值是按本机摄像头标定的**，不是照抄 see-now 的屏幕口径（屏幕静止 0.00 分，摄像头静止也有 1.9 分）：

| 情形 | 变化分 |
|---|---|
| 静止 / 传感器噪声 | p50 = 1.9，p90 = 6.5，p99 = 11.0 |
| 平移 15px / 30px / 60px | 22.7 / 37.4 / 59.5 |
| 亮度 ±15%（自动曝光） | 22 ~ 30 |
| 一个人入画（占宽 12%） | 7.9 |

于是 `cutAbs` 定在 12（噪声碰不到、真实事件够得着）、`refScore` 定在 5（安静房间 3 秒攒不到 180 分）、`dupMin` 定在 3.5（压在噪声地板 p75 = 3.3 之上）。换机器或换摄像头时按这张表重新标一次即可。

**开关**：`localStorage['s2s.voice.sheet'] = '0'` 切回旧的多帧路径做对比，不需要重新构建。

#### 画面在对话里默认收起来（v0.5.0 起）

每一轮语音都带着画面，对话里就多出一张大图——看久了确实有点怪。现在画面默认**收成一个小按钮**（「📷 画面 · 点击查看」），点一下就地展开；工具栏上多了一枚眼睛芯片，能一键全显 / 全隐。

能做到「只收起我们的画面、不动舰长自己上传的截图」，靠的是附件 id：宿主把提示里的图片存成附件时，id 就是**图片字节的 sha256**（`sha256:…`，对象就在 `~/.dsh/attachments/v1/objects/<xx>/<sha>`）。插件对每张发出的画面算一次同样的 sha256，界面就能把两张图区分开。

接管的是宿主的 `conversation.chat.user.images` 槽位（优先级 200，高于宿主自带的 100）；万一宿主换了渲染路径接管不上，还有一层 CSS 兜底把带图附件行藏起来，状态同样记在 localStorage。

**开关**：`localStorage['s2s.voice.hideVision'] = '0'` 让画面永远显示（等于把总开关常开）。

#### 调试口径：盯着一小块看

陪伴场景看的是「整幅画面有没有变」，而调车、盯仪表这类场景看的是「画面里那一小块有没有动」。后者会被全幅平均稀释掉——实测一个人只占画面宽度 5% 时平均分只有 1.11，沉在噪声地板（1.9）下面。所以另外留了一套口径，两处开关：

一是**桥接的 ROI 裁剪**（`bridge-config.json` 的 `camera.roi`，归一化坐标）：

```jsonc
"camera": {
  "enabled": true,
  "device_index": 0,
  "max_side": 640,
  "quality": 60,
  "roi": { "x": 0.25, "y": 0.25, "w": 0.5, "h": 0.5 }   // 只留画面中间那一半
}
```

裁剪发生在取帧之后、缩放之前，之后的 JPEG、指纹、网格都按裁好的画面算——目标占满整幅，任何动作都是大分，模型看到的也是这块放大后的区域。实测 640×480 加 `0.5×0.5` 的 ROI 后返回 320×240。

二是**插件的调试口径**（`localStorage['s2s.voice.sheet.debug'] = '1'`），一改就生效、不用重启：

- 统计量从「全幅平均」换成「**变了多少格**」——逐格算差异，超过阈值的格才算变了。噪声只让零星几格刚过线，真正在动的那一簇会大幅过线，小目标的信噪比好一个数量级
- 打分帧率从 12 fps 提到约 30 fps（遥控器回中那种几百毫秒的瞬变，12 fps 容易整段跳过）
- 积分窗口压到 1 秒、两个留帧点最短间隔压到 0.2 秒
- **事件前回看**：检测到切点时，把之前 3 帧也补进拼图——不然只看得到「滑完之后」，看不到「滑之前是什么样」

> 这套口径只是「看得见有没有动」。要测「滑了几厘米、花了多少毫秒」，得在底盘上贴 ArUco 之类的标记、录一段视频做光流或位姿解算，那是另一条路。

> 拼图路径需要新版桥接（`/api/camera/frame?grid=1` 返回 `grid` 字段）。旧桥接照样能跑——拿不到网格时退回单帧路径。

画面小窗显示的是**摄像头实时画面**，底下一行单独写「模型最后收到 X 秒前」——两件事分开展示，免得把「摄像头现在看到的」和「模型手里那一帧」混为一谈。

> 拼帧那部分移植自 dsh-see-now（SAOS-3624，Apache-2.0），署名与许可文本见 `src/client/voice/seenow/NOTICE`。
